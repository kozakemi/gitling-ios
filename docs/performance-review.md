# 分支切换与状态页性能检查

检查日期：2026-11-10。基准环境：Xcode 27.2，iPhone 17 / iOS 27.0 模拟器，Debug 构建。测试数据由 XCTest 临时创建，完成后删除。

本轮复查保留了上一轮 P2 修复：外部工作区、LFS 根目录规则和 SSH 端点、Push 指针生命周期、File Provider 同步锚点，以及测试与 CI。新增工作集中在交互延迟。

## 确认的调用链问题与修改

| 问题 | 原来的代价 | 当前处理 |
| --- | --- | --- |
| 页头使用 `summary()` | `summary()` 为判断 dirty 扫描工作区；状态页随后再次调用 `status()`，重复扫描 | 新增 `header()`，只读 refs/config，一次打开读取当前分支、分支列表、远程和工作区位置 |
| 操作结束调用完整 `reload()` | 切换一个仓库的分支也重新扫描全部仓库，耗时随仓库总数增长 | 操作完成仅刷新受影响的仓库；启动、主动刷新和重新激活仍可完整刷新 |
| 路径查询隐式调用 `publish()` | 每次打开仓库、解析工作区书签都枚举仓库存储和备份目录；首次复制可很大 | 路径查询不再做迁移；启动迁移在后台执行一次，结构性操作按需发布 |
| 主线程同步 I/O | 文件浏览、控制台、文件预览、配置页和操作前的远程配置查询可能阻塞界面；部分操作还会等 Git 全局锁 | 文件和 Git 读取移至后台，主线程只更新显示和账户状态 |
| LFS 每次状态刷新重算哈希 | 每次读取所有 LFS 内容到内存并计算 SHA-256，成本随文件总字节数增长 | 仅验证 libgit2 报告变化的候选路径；使用有容量上限的缓存及流式 SHA-256 |
| 状态读取使用全屏遮罩 | 无改动仓库每次打开状态页都遮挡页面，无法继续切换页签 | 状态区内显示加载指示器，保留已有内容；读取失败显示错误，避免将失败当成“无修改” |
| 多次刷新交错 | 快速切换页签/筛选条件可能继续处理过期结果 | 取消旧刷新任务，检查 generation 和取消状态后再继续或更新界面 |

LFS 缓存检查设备、inode、大小、mtime、ctime 和期望 OID。同大小修改、恢复 mtime、分支指针变化均不能直接复用旧结果。哈希计算前后再次检查文件状态；符号链接不作为普通 LFS 内容命中缓存。未变化文件仍要执行轻量元数据检查。

## 实测结果

创建含 2,000 个已提交文本文件的仓库，两条分支仅有一个文件不同。每次切回 master 后读取页头和状态，重复 5 次，报告中位数。优化前页头路径为 `summary + branches + remotes`，优化后为 `header`；两者随后均读取 `status + syncCounts`。

| 路径 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 分支检出本身 | 22.44 ms | 18.29 ms |
| 页头 + 状态读取 | 41.98 ms | 16.29 ms |

页头与状态路径减少约 61%。检出本身的差异较小，容易受文件系统缓存和调度影响；主要改善是检出前后的额外扫描与界面阻塞。

额外测试一个 32 MiB 的 LFS 文件：首次验证约 14.31 ms，未变化时重复验证中位数约 0.086 ms。此项比较同一实现的冷缓存和热缓存，不能直接解释为整个状态页的提速比例。

基准没有设置毫秒级通过阈值，避免不同设备和 CI 负载导致测试不稳定。行为测试检查 checksum 缓存失效、目标仓库刷新范围，以及分支切换完成后列表状态与 revision 的一致性。

## 尚需实际设备数据判断的部分

- Git 操作仍由现有全局锁串行执行。长时间 clone/fetch/push 可能使其他 Git 读取等待；本轮已移走主线程上的锁等待，未修改 libgit2 并发策略。
- 真机外部工作区、iCloud 和第三方 File Provider 的文件下载及元数据请求，可能比模拟器本地目录慢很多。本轮基准不覆盖这些提供方的实际延迟。
- 大量文件有实际变更时，检出仍需安全检查并写入对应文件；首次检查 LFS 内容仍需完整校验。
- 取消刷新可以阻止后续工作和过期结果更新，但已经进入 libgit2 或底层文件系统的同步调用仍会执行完毕。

若真实仓库仍出现秒级等待，应分开记录 Git 操作、操作后的列表刷新、详情页状态扫描和外部存储 I/O，避免只根据全屏加载动画判断检出本身的耗时。
