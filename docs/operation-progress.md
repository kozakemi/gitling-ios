# Git 操作进度

日期：2026-11-13。参考本机Android工程 `RepoDetailScreen.kt` 的阶段说明、线性进度和数量提示，iOS补充可读的操作进度；保留现有未提交功能，由Codex直接实现和验证，不调用Cursor或DeepSeek。

## 展示与范围

克隆、抓取、拉取、推送、子模块初始化/更新接入进度事件。界面显示操作名、仓库名、当前阶段、阶段百分比、对象/增量/文件数量、已传输字节和耗时。子模块另显示当前完整路径；重试仍沿用已有的完成项和目标。

阶段包括准备、连接、认证、接收对象、对象索引、解析增量、准备发送、发送对象、等待远端确认、检出文件、合并提交、处理LFS及刷新状态。数据来自libgit2的transfer、pack、push transfer和checkout回调；不会为了计算进度额外扫描工作区、计算总仓库大小或联系远端。

百分比只代表当前阶段，不代表整个操作：接收完成之后仍可能解析、检出、处理LFS或刷新界面。没有可靠总量的连接/认证、合并、LFS、远端确认等阶段使用不确定进度和持续耗时，不显示0/0，不生成虚假的总百分比或预计完成时间。LFS当前只有阶段提示，没有逐对象/逐字节下载进度。未接入详细回调的其他本地操作保留操作名称、准备和刷新提示。

仓库列表/详情使用统一进度遮罩；操作弹窗和子模块页有各自可见的进度，关闭弹窗后主界面仍能看到正在执行的任务。界面不提供会误导为安全回滚的“取消”按钮，既有写锁、失败恢复和数据保护不变。

进度卡随内容收缩，最大高度受视口限制；窄屏、长仓库名/子模块路径和无障碍字号下可纵向滚动。中英日新增21条翻译，数量和耗时使用等宽数字。

## 性能及生命周期

`GitProgressRelay`用锁保护一个最新快照，最多有一个待执行投递，100ms合并窗口将主线程更新限制为约10次/秒，不为每个对象创建UI任务或日志记录。C回调只构造值并投递，不等待主线程，始终保持原Git返回语义；未传入进度处理器时不安装transfer/checkout回调。

凭据与回调上下文在同步C调用期间保持存活；传输回调和检出回调共享明确的上下文。每次操作拥有独立UUID，完成或失败时使relay和当前UUID失效；刷新阶段不能被迟到的传输消息覆盖，也不会把上一任务的100%带到新操作。

只显示本地定义的阶段、计数和校验过的子模块路径，不展示服务端sideband文本、远端URL或凭据。
