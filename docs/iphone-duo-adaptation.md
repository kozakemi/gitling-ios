# iPhone Duo 适配验证

验证日期：2026-11-10。使用 Xcode 27.2 自带的 iPhone Duo / iOS 27.2 模拟器；另建 `Gitling Duo Layout QA`，与用户现有模拟器隔离。设备配置的外屏为 466×678 点，展开内屏为 951×669 点。测试仓库均为本地副本，没有重新连接 Git 服务器。

## 修改

- 仓库列表采用标准 NavigationLink；限制双栏侧边栏宽度。详情导航以仓库选择为身份，切换仓库时同时重置页面状态和导航目的地，避免旧仓库的分支、历史或 diff 留在新仓库中。折叠和窗口尺寸变化不改变此身份。
- 分区选择器在常规宽度下填满详情列；不足 320 点或字体达到 XXXL 时使用菜单，保留全部四个入口。
- Stash 操作按钮根据可用宽度横排或纵排，保留完整操作名称。
- 无障碍字号下将逐文件暂存操作放在文件名下方；普通字号下保留横排，并保护按钮文字所需宽度。
- 提交行按内容增高，摘要最多显示两行，分支标签独占一行；提交图贯穿实际行高，最多占 84 点，避免多分支图挤走提交文字。超过六列时图形压缩，完整 Git 拓扑数据仍保留。

以上逻辑根据窗口宽度和 Dynamic Type 工作，没有按机型或铰链角度执行 Git 重载。

## 自动回归

`AdaptiveLayoutTests` 新增五项回归，使用 UIHostingController 测量实际 SwiftUI 布局，并验证导航状态生命周期：

- 窄列中操作组转为纵排。
- 中、英、日操作文字在 280～951 点宽度及无障碍字号下不超出容器。
- 分区选择器在 240～619 点宽度和多个字号下可布局。
- 大字体提交行增高，密集提交图宽度有界。
- 同一仓库从展开尺寸变为外屏尺寸保留状态；切换到其他仓库再返回时重新建立状态。

完整测试还包括既有数据完整性、复制导入、Stash、分支与上游、逐文件暂存，以及用户真实仓库的离线分支切换和历史分页性能测试。性能数字是模拟器中 Git/缓存调用耗时，不是屏幕帧率或真机耗时。

结果：Duo / iOS 27.2 与 iPhone 16 Pro / iOS 18.6 各 82 项测试全部通过，真实仓库的四项离线测试均执行。通用 iOS 设备 Release 构建通过。

日志与结果包保存在被 Git 忽略的 `build/duo-tests-final.log`、`build/duo-ios18-tests-final.log`、`build/duo-release.log`，以及对应 DerivedData 的 `Logs/Test` 目录。

操作组测试最后改用实际 bordered Button 进行测量；在 Duo 上额外重跑五项布局回归，5/5 通过。iOS 18.6 的最终完整回归也包含这些按钮测量。

## 可视检查

在独立 Duo 模拟器上操作并检查了：

- 外屏竖向的仓库列表、文件浏览和提交历史；长分支标签不会挤走作者信息。
- 展开内屏的双栏布局，以及旋转后的单栏布局。
- 提交页面从外屏展开、旋转，再折叠到横向外屏，仍停留在同一仓库的提交页面。
- 半展开状态下选择第二个仓库，分支变为 `qa/second-repository`，文件变为该仓库的 `second.txt`。
- 外屏状态页的中文长路径及取消暂存按钮、对应的逐文件 staged diff，内容位于安全区域内。
- Stash 在外屏纵排三个操作，展开后的表单中恢复横排；输入框弹出软件键盘后再折叠，输入框和保存入口仍可见。

窗口尺寸、字体和多语言的自动布局测量与上述可视检查互补；自动测试没有测量屏幕帧率。

## 性能观察

首轮 Duo Debug 离线测试中，16 个差异路径的分支切换中位数为 53.65 ms，471 个差异路径为 320.97 ms；全部分支前 300 条历史为 4.47 ms。最终完整回归与另一个模拟器同时运行时，分别为 67.61 ms、611.91 ms 和 8.60 ms。宿主负载和文件缓存差异明显，这些数字不能用于认定 UI 帧率或性能回归；本轮没有增加网络访问或每次铰链角度变化的仓库扫描。

## 验证边界

这是模拟器适配验证，不能替代真机的触控、折痕、硬件键盘和 GPU 帧率测试。后续应在真机补充连续折叠、后台恢复和 Instruments 卡顿分析。
