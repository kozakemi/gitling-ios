# 文件历史、历史版本与 Blame

更新日期：2026-11-12。

## 使用与范围

文件预览页顶部提供“内容 / 文件历史 / Blame”切换。三者均为只读：不修改 HEAD、引用、索引或工作区，路径校验拒绝空路径、`..` 越界及 `.git` 内部路径。

- 文件历史从 HEAD 沿首父遍历，只列出改变该文件的提交。合并提交只与首父比较，仅存在于被合并分支上的提交不显示，相应修改计入合并提交。路径在首父中不存在时，用 Git 默认相似度检测（`git_diff_find_similar`，仅 `GIT_DIFF_FIND_RENAMES`）寻找重命名来源；找到则继续跟随旧路径，否则视为新增并停止。不检测复制，不查看其他父提交。目录路径会被拒绝。历史游标按拓扑加时间排序持续 revwalk，分页不重复从头扫描。
- 历史版本按完整提交 OID 读取，先读对象头判断大小，结果为文本、缺失、二进制、超过256 KiB、非 UTF-8、符号链接（只显示目标，不跟随）、子模块、目录或对象缺失之一。
- Blame 对比工作区文本与一次性读取的 HEAD。工作区文件须为不超过256 KiB、无 NUL 的 UTF-8 普通文件；HEAD 中的版本也须为不超过256 KiB 的非二进制普通 blob，符号链接、子模块和目录会被拒绝。与 HEAD 不同的行显示为未提交，未跟踪文件整体显示为未提交。blame 使用 `GIT_BLAME_FIRST_PARENT`，`newest_commit` 固定为读取到的 HEAD OID，读取后分支移动不影响结果。

## Blame 串行与取消

所有 blame 经 `BlameQueue` 在单一后台队列串行执行。同一仓库、路径与仓库修订的请求共享一个任务。等待者取消后立即收到 `CancellationError`；最后一个等待者离开时任务令牌被取消；排队期间已无等待者的任务轮到时直接跳过，不做任何工作。

`git_blame_file` 和 `git_blame_buffer` 是同步调用，没有取消或进度回调，一旦进入就会运行到结束，结果随后丢弃。其间 CPU 和内存继续占用，后续 blame 排队等待（队头阻塞）。

取消令牌在打开仓库前、每次 libgit2 blame 调用前后检查；预遍历中，每个提交、每个被跟随路径、每个树差异条目、每个候选 blob、重命名检测前后及其每个结果条目都会检查。以下单次同步调用不可中断，只能在调用之间响应取消：`git_diff_tree_to_tree`、`git_diff_find_similar`、提交与树的读取，以及路径查找。因此在一次包含大量文件或巨大树的提交上，取消延迟取决于单次差异调用的耗时。文件历史的重命名检测使用相同的检查点。

## 预算与截断

blame 开始前，预遍历沿 libgit2 将走的首父链估算读取量，并据此设置 `oldest_commit`。默认上限（`BlameLimits.standard`）为5000个首父提交及64 MiB。计入的内容如下：

- HEAD 中的文件版本；
- 每一步父提交中每个被跟随路径的版本。libgit2 每步都读取其当前来源路径的父版本；在有变化的步骤中，它还会为差异报告的每个被跟随路径读取父版本，包括已删除的路径；
- 有变化的步骤中，新增与删除同时存在时的全部新增及删除 blob，因为重命名检测可能比较其中任意一对。

被跟随路径集合模拟 libgit2：任何重命名到被跟随路径的来源都会加入集合，而不只是当前文件的来源。超过提交数或字节预算、遇到超过256 KiB 的 blob 或缺失对象时，预遍历在当前提交截断。该提交上的行标记为 `historyLimited`，界面提示“未检查这次提交之前的历史，这些行可能更早。”

该预算是逻辑（未压缩）大小的估计，取自对象头，不是峰值内存、CPU 或耗时的硬上限。以下内容不计入：pack 增量链的基对象、树与提交元数据、差异与相似度计算的内部结构、libgit2 缓存。预遍历在路径新增步骤自行执行一次重命名检测，会在预算检查通过后实际读取候选内容，因此这部分会被读取两次。树差异的规模不受预算约束。

## 已知边界

- 结果限定首父历史；不检测复制，重命名只依赖默认相似度阈值。
- 预遍历基于当前随附 libgit2 版本的 blame 行为建模。升级 libgit2 后，需要复核来源选择、路径集合与重命名检测是否仍然一致。
- 单次 libgit2 调用无法中断，被取消的 blame 仍会完成当前调用，并阻塞随后排队的 blame。
- 工作区文本只在开始时读取一次；blame 期间对文件的修改不会反映在本次结果中。

## 回归与验证

数据层覆盖首父与合并、分页及空提交计数、重命名跟随与不相似替换、删除与各种 blob 状态、对象缺失与路径越界、只读保护、HEAD 固定、取消、未出生仓库、高亮，以及超大版本、超大重命名候选与预算截断。队列测试用阻塞闭包代替不可中断的 libgit2 调用，覆盖立即离开、任务共享、无等待者跳过及单一并发；所有等待均有超时，测试拆除时释放阻塞闭包、取消所有任务并等待工作队列清空。布局测试覆盖顶部切换控件在中英日、240至951点宽度及无障碍字号下的表现。

本轮新增两项回归：

- 一个只有两次提交、单次删除200个文件并新增200个文件的仓库：在预遍历中途取消即停止，不再调用任何检查点，也不启动 libgit2 blame；
- 已删除的被跟随路径的旧版本超过256 KiB 时在其之前截断，同结构但旧版本较小时可走到根提交。
