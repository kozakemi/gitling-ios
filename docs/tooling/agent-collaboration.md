## 分工与调用

1. **Codex规划**：检查当前代码及用户未提交修改，明确范围、验收标准、允许文件、性能和布局要求。记录本轮基线和已有测试，拆成能独立验收的小批次。
2. **Cursor优先实现**：通过`local_agent_runner.agent_start`提交`backend=cursor`、`mode=read_only`任务。要求读取实际代码后返回统一格式补丁及说明，不写文件，不执行测试、模拟器、提交或推送。
3. **DeepSeek后备**：Cursor返回空结果、失败终态、超时、协议错误或明确能力限制时，记录job ID及错误，确认它已终止，再把同一批次和失败证据交给`backend=deepseek`。不对已经成功应用的补丁重复执行。
4. **Codex校验并应用**：取回完整结果，不把日志草稿当最终补丁；核对任务基线和当前文件，拒绝越界路径、符号链接穿越、未授权文件、凭据或配置修改及无法完整应用的补丁。保留用户原有修改，不reset/clean。需要调整实现时重新下发针对性修正。
5. **Codex独立审查与测试**：检查数据保护、只读/写锁、并发、错误路径、资源预算和界面适配，实际运行相应回归。把准确的编译错误、测试失败或审查意见优先反馈Cursor；功能失败不是立即换后端的理由。
6. **交付**：报告修改、实际验证及剩余边界，更新文档。仅在用户本次授权时commit/push；子代理不能自行提交或推送。

首版MCP保持只读，补丁的产生不需要给代理写盘权限。Codex应用补丁属于用户授权的当前开发任务；它不是将MCP改为任意代码执行服务。若后续确需代理直接写入，应单独设计隔离副本和可审查补丁导入，不能通过force/yolo或取消沙箱来绕过。

## MCP结果与证据

- `agent_backends`核对可用后端及工作区别名。
- `agent_start`返回job ID；`agent_status`与`agent_events`查看状态和增量事件。
- 仅在`succeeded`时用`agent_result`的`nextOffset`取回全部结果，检查`hasMore=false`。
- `accepted=true`仅表示取消请求已接收，应继续查询直至终态。超时或失败不代表已经得到有效补丁，不将partial当最终结果。
- 区分“代理完成报告”“补丁有效并已应用”“Codex实际测试通过”，三者分别记录。
- 当前对话未热加载工具时，可以使用官方MCP SDK的stdio客户端调用注册的同一服务器；仍走MCP协议和同一任务存储，不直接运行Cursor/DeepSeek CLI绕过调度。

## 受控续接与后端交接（0.2，2026-11-12）

- 首轮用`agent_start`创建开发任务，保留返回的`taskId`、`conversationId`和`jobId`。后续同一任务将审查意见、准确失败与新增要求交给`agent_resume(jobId=最新成功轮次, prompt=…)`；不用每轮重新start。工作区、后端及只读策略绑定，不能传入任意原生session ID。
- 变更检查点在worker真正执行时生成，比较上一轮开始时与当前代码的HEAD、索引及有界路径哈希，要求模型重读变化文件；普通续接不重复灌入完整任务和报告。用`agent_context`查看实际传递的上下文及不完整/截断标记。父代理仍要提供精确审查意见，不假设模型有无限上下文。
- 仅对最新且成功的轮次原生续接。终态失败/超时/取消/中断可能留下部分CLI历史，不静默继续。Cursor明确失败后，可对该任务最新终态调用`agent_handoff(backend=deepseek)`，由服务生成有界交接摘要；同一个taskId，新conversation及新后端会话。工作区绑定保持，摘要中的模型结论仍需独立核验。
- 只有一个续接可以推进最新轮次指针。并发、旧父轮次、工作区inode替换、后端入口或策略变化、后端意外返回新SID均拒绝；旧版job仍能查结果，但不能作为外部会话接管入口。排队续接取消后不自动回退指针，需要显式新任务或后端交接。
- 仍是只读委派：本次补充回归与真实模型验证均不运行模拟器、不访问原Git服务器；iOS模拟器白名单和Codex独立应用/测试分工不变。

本轮Cursor完整补丁任务失败或超时，DeepSeek完整任务也超时；缩小为绑定函数后DeepSeek返回结果，Codex发现并修正配置结构与权限描述错误，再完成其余集成、回归和实际验收。没有将失败任务或代理自述算作实现/测试完成。最终证据见独立工程[验证记录](/Volumes/ExternalSSD/git/agent-runner-mcp/docs/verification.md)。
