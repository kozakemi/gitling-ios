# Gitling iOS 当前进度

这是可用演示，不是第一期完成。对照见 `docs/需求与计划.md`。`.git` 留在 App Group，Application Support 留一份备份。不选工作文件夹时，仓库出现在「文件」App 的 Gitling 位置，且不显示 `.git`。选了文件夹时，工作区在该位置下的仓库名目录里，Gitling 位置打开的仍是那个目录。已连接的 GitHub/GitLab 账户可以在克隆页选择自己的仓库。未签名运行读不到 App Group，Gitling 位置会是空的。

## 演示里已经有的

- Xcode 工程，部署目标 iOS 18，iPhone 与 iPad。Bundle ID 为 `com.maneeshacooray.gitling.ios`，版本 0.1.0。许可证为 GPLv3。
- SwiftUI 标准分栏、工具栏、表单和弹出层。忙碌提示使用系统材质。没有自绘玻璃。界面文案为英文、简体中文和日语。
- 主页用固定的大标题 Gitling 和仓库数量，下面是固定搜索框、右上角设置、右下角加号。仓库列表、删除确认、本地初始化、只接受 `https://` 的克隆。克隆和新建可以选择一个文件夹；已有仓库可以关联或取消关联。账户令牌按账户写入钥匙串。姓名和邮箱存在本机设置里。
- 关联后，文件列表、状态、提交和「文件」App 都读取该文件夹。取消关联会把当前提交检回应用目录，外部文件保留。该选择不针对某一个外部应用。
- 文件、提交、状态、终端四个页面。详情列使用独立的 NavigationStack，从提交差异返回时停留在仓库详情，不会跳回主页；详情加载只读取当前仓库，不再扫描全部仓库。提交差异用 UITextView 左对齐显示，并按行着色：新增绿色、删除红色、hunk 蓝色、文件头灰色；超过 256 KB 的文件按二进制处理，避免大 diff 卡死。提交历史按分支画连线，可以只看当前分支或所有分支，点开一条提交能看到说明和差异。提交详情在后台生成 diff，大提交不会阻塞界面；提交图用固定行高的全高画布，相邻行的车道在边界处连续；提交行左对齐，并显示 HEAD、本地分支和远程分支标签。状态页显示工作区概况。终端接受 `status`、`log`、`diff`、`branch`、`help`，按命令分发，不是外壳。
- 操作菜单分为同步、更改、分支、文件、远程、仓库。可以抓取、拉取、推送、暂存、提交、硬重置、新建并切换分支、合并、变基到另一条本地分支、按提交号拣选、新建文件或目录、添加或删除远程、查看配置。关联和取消关联也在这个菜单的仓库一节里。变基或拣选遇到冲突时列出冲突文件并中止，分支保持原样。
- File Provider 扩展。仓库在「文件」App 的 Gitling 位置下，不列出 `.git`，也不能通过标识进入 `.git`。Git 写操作进行时，外部创建、修改、重命名和删除会被拒绝。仓库本身不能从「文件」App 删除。应用回到前台时刷新工作区。设置页的「在文件中显示」会再次注册该位置，并说明要在「浏览 → 更多 → 编辑」里打开 Gitling。注册失败时显示系统错误。未签名安装包不能加载这个扩展，所以该位置可能不出现。
- 模拟器和没有 App Group 的安装会改用应用 Documents 目录，并在「文件」App 的「我的 iPhone」下显示 Gitling；「在文件中显示」会直接提示打开「我的 iPhone → Gitling」。这条回退路径把仓库（包括 `.git`）放在 Documents 里，`Files` 默认隐藏点文件；已签名且有 App Group 的安装仍走 File Provider，不显示 `.git`。
- 应用图标使用 Android 原版的绿色底和分支标记。强调色为 `#1B5E3A`。
- 账号支持 GitHub Device Flow 和 GitLab Personal Access Token，可绑定多个 GitHub/GitLab 账户。GitLab 支持 GitLab.com 与自建实例（自定义端口和子路径），PAT 需要 read_api、read_user、read_repository、write_repository。新建仓库默认本地初始化；克隆时先选择账户，选中后才加载该账户的远程仓库。克隆成功后仓库记录账户关联，后续拉取、推送优先使用该账户。设置里可以逐个移除账户。
- 初始化时设置 `core.ignorecase=true`、`core.filemode=false`。克隆失败会删掉半成品目录。
- libgit2 1.8.4 静态链接，设备与模拟器都是 arm64。HTTPS 走 SecureTransport，SSH 关闭。源码编译脚本是 `scripts/build-libgit2.sh`。

## 已验证

提交差异页面左对齐显示并带增删颜色；大文件按二进制提示，不再长时间卡住；从提交差异返回后仍停留在仓库详情。

提交历史用两行布局和连续车道渲染，在带合并提交的测试仓库上检查通过；合并提交的分支曲线不再出现多余的竖线；HEAD/分支标签显示在对应提交行上；5000 行 diff 能正常打开和滚动。

在自建 GitLab 19.5 上验证了 PAT 连接、项目列表和通过 Gitling 克隆 `Kozakemi/gitling-ios`；测试用 PAT 已撤销，未写入代码或仓库。

模拟器 iPhone 17 上确认新主页：Gitling 大标题、仓库数量、搜索框、右上角设置、右下角加号；切换中文和日语后标题、数量、搜索提示均跟随系统。iPad 和 iOS 18 上也检查了分栏与回退布局。

模拟器 iPhone 17 上确认过「文件」App 的「我的 iPhone」会显示 Gitling，进入后能看到 `repositories` 里的仓库；未签名和模拟器构建使用 Documents 回退，已签名构建仍使用 File Provider。

模拟器 iPhone 17 上，`GitClientTests.testInitCommitCloneAndPush` 通过。它用本地 `file://` 仓库覆盖初始化、状态、暂存、取消暂存、提交、推送、克隆和拉取。`testLinkedFolderReceivesTheWorktreeWithoutGitMetadata` 覆盖关联外部文件夹、工作区检出、外部目录没有 `.git`、状态读取该目录，以及取消关联后文件仍留在外部文件夹。`WorkingTreeTests` 覆盖隐藏 `.git`、拒绝越界路径、重命名，以及 Git 占用锁时拒绝外部写入。`GitHubAuthTests` 覆盖设备码、轮询状态和「手填口令优先于已保存账号」。还没有在真机上走完一次 GitHub 授权，也还没有在真机的「文件」App 里确认 Gitling 位置。

修过一处句柄生命周期：打开仓库的包装对象如果提前释放，libgit2 会报 `path cannot exist in repository`。现在每个 Git 操作都会把仓库保持到该操作结束。

公网 HTTPS 克隆和证书校验还没有跑过。界面上的克隆入口只允许 `https://`。

## 编译 IPA

```sh
./scripts/build-ipa.sh
```

没有 `DEVELOPMENT_TEAM` 时，产物是 `build/Gitling.ipa`。这是未签名的 Payload 包，不能直接装到设备上。

有团队时：

```sh
DEVELOPMENT_TEAM=团队ID ./scripts/build-ipa.sh
```

默认导出 development 包。需要上架包时设置 `EXPORT_METHOD=app-store-connect`。
