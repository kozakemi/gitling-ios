# 逐文件放弃修改与恢复删除文件

2026-11-11。

在仓库“状态 → 未暂存的修改”中选择文件的“放弃修改…”。确认页显示完整路径、恢复来源与影响；取消不会修改文件。未跟踪文件只有暂存入口，不提供此恢复操作。

## 恢复语义

恢复来源固定为 **索引（已暂存版本）**，不是 HEAD。若已将 A 暂存后又编辑为 B，确认后工作文件恢复为 A，索引仍是 A；其他文件的暂存、未暂存和未跟踪内容不变。工作文件被删除但索引仍有版本时，可以重建该文件及缺失的父目录。

索引不作任何写入，包括其 stat 缓存。新暂存、尚未首次提交的文件同样支持。已暂存重命名的目标按目标路径恢复，不重新创建原路径。操作按字面路径查找索引对象，不把 `*`、`[` 等文件名字符作为通配符。文本沿用 libgit2 的检出过滤（如 CRLF）；二进制按原始字节恢复，可恢复空文件和可执行位。

确认页明确提示未暂存内容会丢失、已暂存内容保留，以及操作无法在 Gitling 内撤销。关联外部工作区时另行提示会修改外部目录中的文件。删除恢复使用单独标题和说明。

## 保护边界

- 冲突索引或未完成的 Git 操作会阻止恢复；确认后才出现的冲突/操作同样拒绝。
- 仅支持普通的索引文件。符号链接（包括悬空链接及索引中的链接）、目录、子模块和没有索引版本的路径拒绝执行；不会递归删除目录。
- 未跟踪文件、已暂存的删除，以及仅在未跟踪目标中存在的重命名文件，不会自动删除或从 HEAD 恢复。要更改暂存内容，应先明确取消暂存。
- 外部工作区通过实际书签和安全作用域访问。书签损坏、目录失联或确认后关联变更时直接报错，不退回内部工作目录，不在解析时重建失联的外部目录。
- 确认绑定索引 OID/模式、实际工作区、父目录身份和工作文件的 inode/大小/模式/修改与变更时间。确认期间重新编辑、重新暂存、替换目录或出现同名文件会拒绝覆盖，要求重新查看。
- 使用仓库写锁与文件协调；协调等待不占用全局 Git 锁。通过目录描述符和 `O_NOFOLLOW` 逐层访问、写入临时文件并同步后原子替换；缺失文件发布采用不覆盖同名目标的方式。失败时清理本次临时文件。
- Git LFS 指针文件暂不支持此操作：明确报错，避免将实际内容替换为指针。恢复不触发网络请求。

## 验证

新增 20 项 `FileRestoreTests` 和 1 项自适应布局回归。覆盖索引优先、未提交仓库、删除及缺失目录、通配符字面路径、暂存重命名、未跟踪/已暂存删除保护、确认过期、冲突、符号链接/目录/子模块、外部工作区及失联保护、二进制/空文件/8 MiB 文件、CRLF/可执行位、损坏对象和 LFS 拒绝。

Duo 隔离 QA 仓库手动完成：展开状态页 → 确认页 → 折叠外屏 → 取消，核对文件与索引均未改变；随后在外屏恢复已暂存后再次编辑的文件、重建已删除文件。最终核对 HEAD 和索引字节完全未变，工作文件恢复为索引内容，未跟踪文件保留，无临时文件残留。长中文路径、按钮和影响说明在内外屏可读；中/英/日及无障碍字号布局在 240～951 点宽度测量通过。未进行真机验证。
