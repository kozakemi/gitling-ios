# Tag 浏览、安全检出与 diff 标签栏布局

## Tag 工作流

入口为仓库“操作 → 标签”。支持搜索、轻量标签、附注标签、嵌套标签和中文/带斜杠的名称。列表只枚举 `refs/tags/` 引用及对象头，不查询提交历史，也不加载全部附注或文件内容。进入详情后显示标签引用 OID、附注作者与时间、说明、最终目标类型/OID，以及目标提交的作者、时间和摘要。

只有最终指向 commit 的标签允许检出；tree/blob 标签可以查看元数据，不读取大文件内容，不允许检出。损坏的标签单独标示错误。过大的元数据或过深的嵌套会明确拒绝，避免无界加载。没有加入 Tag 创建、删除、推送或签名验证功能。

“检出标签”先显示确认页，明确进入 **detached HEAD（分离的 HEAD）**，不会移动任何已有分支或 Tag。确认后重新读取标签，若引用 OID/目标变化或已删除则拒绝。精确查找完整 Tag 引用，避免与同名分支混淆。

检出前要求暂存区、工作文件、未跟踪文件均已处理，并拒绝冲突或未完成的 Git/子模块任务；包含已经检出的嵌套子模块脏状态检查。忽略文件碰撞使用安全检出策略保护，不强制覆盖。外部关联工作区通过实际书签访问，失联时拒绝退回内部工作区。

先锁定 HEAD、来源分支及精确的 Tag 引用，再进行 SAFE + DONT_OVERWRITE_IGNORED 的预检查及检出，最后通过引用事务将 HEAD 写成直接指向目标提交的引用。HEAD、索引或 Tag 的锁冲突会拒绝操作。没有跨进程崩溃的工作区事务回滚保证，也不会为了恢复而强制删除用户文件。

成功后仓库页、标签详情、状态文本和缓存明确展示分离的 HEAD 及提交短 OID；提供“创建分支以保留工作”的入口。可创建分支保留 detached 状态下的新提交，也可以检出原分支返回。分离状态下拒绝把推送变成一个意外的 `HEAD` 分支；“全部分支”历史会纳入当前 detached 提交，避免标签提交不在其他分支中时漏显。子模块和 Git LFS 不会因 Tag 检出自动联网更新。

检出失败的原因由标签详情页显示在操作区域，避免从嵌套确认页关闭时被根页面弹窗吞掉。

## 图片中的 diff 布局问题

触发路径：状态页 → 未暂存文件的差异 → 切换“已暂存的修改”，且该文件没有暂存差异。

原来的 VStack 在有差异或加载中时包含可伸展视图，占满内容区域；差异为空或出错时只有标签栏和短提示，整体收缩，并被导航内容区域垂直居中。因此标签栏看起来从顶部移动到了屏幕中间。

已使用统一 `DiffPanelLayout` 撑满页面，并给内容区域一致的空间与顶部对齐，四种状态共用同一布局。标签栏在正常、空白、错误、加载之间切换时保持顶部位置。窄列或大字号时选择器可改为菜单，避免 Duo 分栏内文字被压缩。

## 回归与验证

新增 17 项 Tag 数据层回归、1 项详情错误回调回归及2项布局回归，共20项。覆盖不同类型/名称标签、只读列表和详情、detached 检出与返回分支、创建分支保留提交、未提交修改/冲突/嵌套子模块保护、过期确认、引用及索引锁、忽略文件与符号链接碰撞、外部工作区、损坏对象、未首次提交仓库中的已获取标签，以及500个额外标签的列表性能。

布局测试在实际 UIWindow/UIHostingController 中按“有差异 → 空暂存差异 → 返回有差异 → 错误/加载”切换，测量标签栏的全局纵坐标，不仅检查视图尺寸。另测中/英/日、240～951 点宽度及无障碍字号下的选择器和 detached HEAD 提示。

测试继续复用既有真实仓库离线缓存执行分支切换、历史加载及复制导入基准。本轮不连接远端 Git 服务器。模拟器采样不能代替真机性能或交互验证。
