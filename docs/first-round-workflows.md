# 第一轮：日常提交工作流

本轮完成逐文件暂存与差异、Stash、分支名和上游管理，保留上一轮数据保护与性能修复。

## 使用入口与行为

- 状态页分为已暂存、未暂存两组。同一文件存在两种版本时会出现在两组中；点击文件查看对应 diff，右侧按钮暂存或取消暂存该文件。
- diff 页面可切换工作区与暂存区；未跟踪文件、删除文件、初始提交之前的差异均可查看。按文件进入时只查询该路径，仍使用 256 KB 二进制判断和 80,000 字符显示上限。
- 提交仅使用索引，不重新暂存工作区。LFS clean/upload 发生在暂存时，单文件操作只处理所选路径，防止把未选择的 LFS 文件一起加入提交。
- 操作菜单的 Stash 页面支持说明、可选包含未跟踪文件、保存、应用、Pop 和确认删除。恢复前要求工作区无待处理修改；恢复会重建暂存区与工作区的区别。
- Stash 操作根据 OID 重新定位条目，避免列表索引变化后误操作。Pop 仅在应用成功且索引无冲突时删除。冲突时保留 Stash 和双方内容，状态页显示冲突，用户可通过外部编辑器解决后逐文件暂存；本轮未提供内置三方冲突编辑器。
- 创建分支使用 libgit2 的名称校验，允许 `feature/topic`。操作菜单的“管理分支与上游”支持重命名、设置/清除上游、安全删除。删除仅允许非当前分支且提交已合入当前分支，不提供强制删除入口。
- Fetch/Push 可选择远程，自动模式优先使用上游远程，无上游时回退到 origin 或唯一远程。Pull 始终跟随已配置的远程上游。默认 Push 使用上游实际分支名，例如本地 `work/topic` 跟踪 `company/master` 时推送到远程 master。
- 显式 Push 到另一个远程不会覆盖已有上游。首次 Push 成功后设置上游。凭据按实际远程地址（Push 使用 pushurl，如有）匹配；绑定到另一主机的账户不会被直接复用。

## 回归覆盖

`FirstRoundWorkflowTests` 覆盖部分暂存后的再次编辑、只提交选中内容、字面路径中的通配符字符、未产生 HEAD 时取消暂存、文件删除与重命名、单文件 LFS clean、LFS 取消暂存后的索引比较、Stash 暂存区/工作区/未跟踪文件往返、冲突 Pop 保留 Stash、空/初始仓库失败保护、外部工作区、分支校验/重命名/保护删除、多远程和不同名上游、跨主机账户匹配。

完整测试入口：

```sh
./scripts/test.sh
```

原有的数据丢失回归、同步锚点、LFS 缓存和定向刷新测试仍全部保留。

## 性能

- 元数据和 Stash 列表按页面加载，不扫描每个仓库的历史或状态。
- 逐文件暂存修改一次索引；逐文件 diff 使用字面路径过滤，耗时工作在线程池执行。
- LFS 暂存沿选中路径的父目录查找属性文件；目录枚举跳过 `.git` 子树。
- 状态判断以索引中的 LFS 指针为准，避免取消暂存后被旧清单误判为干净。识别指针先读取 Git 对象头，仅加载小对象，避免为判断指针解压普通大文件。
- 2,000 文件模拟器基准中，单文件暂存加 diff 的中位耗时约 4.3 ms；同时运行多个模拟器与 Release 构建时约 7.9 ms。基准不设置固定毫秒通过阈值。
