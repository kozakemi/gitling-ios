# Gitling iOS 需求与计划

本文描述 iOS 客户端要做成什么样，以及按什么顺序做。不排期，也不写日期。Android 工程在 `/Volumes/ExternalSSD/git/Gitling`，只作为行为参照，不迁移其 Java / Kotlin 源码。

## 1. 已确认的决定

- 新产品重写。界面用 SwiftUI，Git 用 libgit2，SSH 用 libssh2。
- 最低系统为 iOS 18。iPhone 与 iPad 都要能用。
- Git 数据放在本应用的容器里。用户可以在「文件」App 中选择任意文件夹作为工作区，做法与 Working Copy 相同。该文件夹里不写入 `.git`。
- 未选择外部文件夹时，工作区留在应用内，并通过 File Provider 出现在「文件」App 的 Gitling 位置。
- 不内置文本编辑器。改文件交给任何能打开该文件夹的应用。Obsidian 只是这类应用的一个例子，不是单独支持的对象。
- 许可证保持 GPLv3，并随应用提供对应源码。
- 界面跟随系统的 Liquid Glass。iOS 18 用系统材质，iOS 26 与 iOS 27 由系统组件呈现玻璃，不按系统版本各做一套皮肤。

这些决定来自对 Android 工程的可行性分析和随后确认的存储方案。下面的假设不阻塞开工，若要改，改文档再改实现。

## 2. 开工假设

- 产品名仍是 Gitling。Bundle ID 与 Android 的 `com.maneeshacooray.gitling` 分开，在建立 Xcode 工程时确定。
- 分发目标是 TestFlight 与 App Store。加密使用系统 HTTPS 与 SSH，按苹果的出口合规问卷申报豁免，不自带私有加密算法。
- 第一期界面语言为简体中文、英文和日语，跟随系统语言。Android 上的其余语言以后补。
- 第一期使用系统字体，并支持动态字号。Android 里的 Plus Jakarta Sans、Inter、JetBrains Mono 不进入第一期。
- GitHub 登录继续用 OAuth Device Flow，可以沿用现有 client id。令牌和私钥口令放钥匙串。
- 不移植 Android 的「共享媒体存储」开关、壁纸动态取色，以及应用内 APK 更新检查。

## 3. 目标

让一个人在 iPhone 或 iPad 上克隆仓库、查看历史和差异、提交并推送。Gitling 持有 Git 数据。用户在「文件」App 中选择工作区位置，再用任意应用修改这些文件，然后回到 Gitling 提交并推送。

成功时的主路径：

1. 用 GitHub 登录，或填写 HTTPS 地址和令牌。克隆时可以在「文件」App 中选择文件夹，也可以只放在 Gitling 里。
2. 选了文件夹时，工作区文件出现在该位置，里面没有 `.git`。没选时，在「文件」App 的 Gitling 位置看到该仓库，且看不到 `.git`。
3. 用任意应用打开该文件夹，修改一个文件并保存。
4. 回到 Gitling，状态页能看到这个文件，暂存、提交、推送成功。
5. 另一台设备拉取后，能得到同一个文件。

## 4. 不做什么

- 不把 JGit、Jetpack Compose 或 Android 界面层搬到 iOS。
- 不把 `.git` 放进用户在「文件」App 中选择的文件夹，无论该文件夹在本机、iCloud Drive，还是其他应用提供的位置。工作区文件可以放进这个文件夹。
- 不在应用内编辑或预览富文本，也不为某一个外部应用做专门集成。
- 不做 Git LFS、裸仓库、worktree、交互式 rebase 和自定义 merge driver。
- 不提供通用终端，也不打包 `git` 可执行文件。
- 不用自绘模糊层模仿 Liquid Glass，也不把玻璃用在正文、差异和提交列表上。
- 不实现 Android 的 Material You 动态取色。

## 5. 需求

### 5.1 系统与界面

最低部署目标 iOS 18.0。在 iOS 18、当前的 iOS 26，以及 iOS 27 上，导航和操作区都使用当时系统的标准外观。

界面规则：

- 导航栏、标签栏、边栏、底部工具栏、表单和弹出层使用 SwiftUI 标准组件。这些组件在 iOS 26 及以后自动采用 Liquid Glass，在 iOS 27 上继续跟随系统，应用不再为新系统单独换肤。
- 自定义玻璃只允许出现在少量浮动操作上，并且只在 iOS 26 及以上调用 `glassEffect`。多个相邻玻璃控件放进同一个 `GlassEffectContainer`。iOS 18 上这些控件退回普通按钮，不模拟玻璃。
- 玻璃只用于操作层。文件内容、差异、提交说明和列表行保持不透明的内容层。
- 遵守系统的「降低透明度」「增强对比度」「减弱动态效果」，以及用户为 Liquid Glass 选择的外观。标准组件自行适应；自定义玻璃在降低透明度时必须仍能读。
- iPhone 使用标签式主导航。iPad 使用侧边栏加详情的分栏。旋转和分屏时，仓库与当前目录状态保持不变。
- 颜色跟随系统浅色与深色。强调色使用固定的品牌色，可加在系统控件的 tint 上。
- 所有可点击文字跟随动态字号。差异和代码使用等宽字体。

### 5.2 仓库放在哪里

每个仓库的 `.git` 放在 App Group。这是「文件」App 里 Gitling 位置读取的目录。应用自己的 Application Support 保留一份备份：启动和每次写完仓库后，把只存在于一边的仓库和书签复制到另一边，不把唯一副本移走。没有开发团队时，模拟器使用本地临时签名，把 App Group 权限写进签名；自动签名或未签名安装会丢掉这项权限，文件扩展就读不到仓库，Gitling 位置是空的。用户给仓库起名字。克隆或新建时，可以用系统的文件夹选择器在「文件」App 中选择一个位置；工作区文件放在该位置下、以仓库名命名的文件夹里。不选则工作区就在 App Group 的仓库目录里，并出现在「文件」App 的 Gitling 位置，其中不显示 `.git`。选了位置时，Gitling 位置仍列出该仓库，打开的是所选文件夹。

选择外部文件夹时，应用保存安全范围书签。之后每次打开仓库，都重新解析书签，并把 libgit2 的工作区指到该文件夹，且不在其中写入 `.git` 文件。检出使用安全策略，不覆盖文件夹里已有的不同内容。检出成功后，应用目录里只保留 `.git`。取消关联时，把当前提交的文件检回应用目录，外部文件夹里的文件保留不动。

删除仓库时删除应用内的该目录及其 `.git`，并删除书签。删除前需要确认。不删除用户选择的外部文件夹。

导入已有仓库时，从用户选择的文件夹或 ZIP 复制进上述根目录。复制完成前写到临时目录，成功后再换名进入正式位置。失败时删除临时目录。以下情况拒绝导入并说明原因：没有 `.git` 目录、选中的是 `.git` 本身、裸仓库、`.git` 是指向别处的文件、ZIP 中没有仓库或有多个仓库、ZIP 路径逃出目标目录。

导入时关闭 `core.filemode`。符号链接在本应用容器内可以保留；若来源仓库依赖会在状态里吵闹的权限位，按 Android 现有行为关掉 `core.filemode`。`core.ignorecase` 在克隆和导入时设为 `true`，因为 iOS 默认卷不区分大小写。

已有仓库可以在详情里关联或取消关联一个「文件」App 中的文件夹。取消关联不删除该文件夹中的文件。

### 5.3 给「文件」App 和其他应用看的目录

应用实现 File Provider 扩展，在「文件」App 中出现 Gitling 位置。每个仓库的工作区是一个文件夹。若仓库关联了外部文件夹，这个位置列出的是该文件夹里的文件。用户需要在「文件」App 的「浏览」里点更多按钮，再点「编辑」，打开 Gitling。未签名的安装包不会加载这个扩展。

规则：

- 枚举和读取工作区文件。允许创建、修改、重命名和删除工作区文件，这样其他应用才能保存修改。
- 不列出 `.git`，也不能通过文档标识解析到 `.git` 里面。
- 一次只允许一个会改写工作区的 Git 操作。操作进行中，File Provider 拒绝写入、创建、删除和重命名，避免和检出、拉取、合并同时改同一棵树。
- Git 操作开始前，假定外部写入可能尚未落盘；提交和状态扫描读取已协调完成的文件内容。
- 扩展进程不能在应用尚未初始化时崩溃。仓库列表尚未就绪时，位置显示为空。
- 用户未授权的第三方应用不能绕过系统文件界面直接访问仓库。

这个位置不绑定某一个外部应用。用户在克隆或详情里选择「文件」App 中的任意文件夹，工作区就放在那里。没有关联外部文件夹时，其他应用打开 Gitling 在「文件」App 中的位置即可读写该仓库。

没有 App Group 的开发安装（模拟器、未签名或重签名丢失 App Group）无法加载扩展。此时应用把工作区放在自己的 Documents 目录，借助 `UIFileSharingEnabled` 与 `LSSupportsOpeningDocumentsInPlace` 在「文件」App 的「我的 iPhone」下显示 Gitling。该回退路径不隐藏 `.git`，只用于本地开发；正式签名安装仍以 File Provider 位置为准。

可选、默认关闭：初始化或克隆后提供一份忽略模板，用来忽略编辑器自己的状态文件。不自动改写已有仓库的 `.gitignore`。

### 5.4 克隆、远程与账号

支持：

- 克隆 HTTPS 仓库。地址形如 `https://主机/路径`。
- 克隆 SSH 仓库。地址形如 `ssh://用户@主机/路径` 或 `ssh://用户@主机:端口/路径`。SSH 必须带用户名。
- 在本地初始化一个空仓库。
- 添加、删除远程，并对选定远程执行 fetch、pull、push。
- 记住每个远程使用的凭据类型：GitHub 账号、自定义账号、用户名加口令或令牌、SSH 私钥。

GitHub：

- 设置里一次完成 Device Flow。打开系统浏览器，展示用户短码，轮询直到成功、拒绝或过期。
- 令牌放钥匙串。之后对 `github.com` 的 HTTPS 远程自动使用该令牌。
- 可以退出账号并删除钥匙串中的令牌。

自定义账号：

- 用于 Forgejo、Gitea 或其他 Git 主机。
- 字段为显示名、用户名、个人访问令牌、实例根 URL。
- 克隆、fetch、pull、push 到该主机时自动带上用户名和令牌。

凭据不写进仓库的 `.git/config` 明文口令字段，也不进用户偏好的明文。

### 5.5 Git 操作

行为与 Android 版对齐，由 libgit2 完成。

仓库列表：

- 展示本地仓库、当前分支、干净或有改动。
- 搜索仓库名。
- 置顶。置顶项排在未置顶项之前。
- 自定义标签，并按标签过滤。
- 进入仓库、删除仓库。

仓库内：

- 文件树：浏览目录、打开文本文件只读查看、查看某文件的提交历史。大文件设定体积上限，超过则提示外部打开，不把整个文件读进内存。
- 提交历史：作者、时间、说明、短哈希。可复制完整哈希。支持在历史中搜索说明。
- 提交图：在历史旁绘制车道，标出分支、标签和 HEAD。这是自绘内容层，不是玻璃控件。
- 差异：工作区差异，以及两个提交之间的差异。
- 逐行 blame。
- 状态：未暂存、已暂存、未跟踪。单个文件暂存或取消暂存，也支持全部暂存和全部取消暂存。
- 提交：填写说明，使用设置中的用户名和邮箱。
- 检出分支或标签，创建分支，合并。
- 将单个文件检出为 HEAD 版本。
- rebase、cherry-pick、reset。冲突时停止并列出冲突文件，不提供三方合并编辑器；用户在外部应用改完文件后，再标记已解决并继续。
- 子模块的 init 与 update。
- 控制台只接受固定命令：`status`、`log`、`diff`、`branch`、`stash`、`fetch`、`pull`、`submodule`，以及帮助。未知命令返回帮助文本。输入可以带或不带前缀 `git`。

长操作（克隆、fetch、pull、push、rebase）显示进度，并可取消。取消后仓库必须仍可打开：克隆失败不留下半成品目录，其他操作停在 Git 自身的安全状态。

应用进入后台时，系统可能很快挂起进程。长操作只保证前台完成。进入后台时保存进度说明；若进程被挂起导致中断，回到前台后报告中断，不假装已经成功。

### 5.6 SSH 密钥

- 生成 ed25519 密钥，也可生成 RSA。私钥加密保存。
- 导入已有私钥。支持带口令的私钥，口令放钥匙串。
- 导出公钥，便于复制到 Git 主机。
- 重命名、删除。删除时说明哪些仓库仍引用它。
- 克隆和推送时选择一把密钥。

### 5.7 设置

- Git 用户名、邮箱。
- 账号管理：GitHub 与自定义账号。
- SSH 密钥管理入口。
- 浅色、深色或跟随系统。品牌色作为强调色，不提供动态取色。
- 关于页：版本号、GPLv3 说明、源码获取方式。
- 不提供仓库根目录搬迁，不提供应用内下载安装包。

### 5.8 小组件

主屏幕小组件展示已选仓库的分支，以及干净或有改动。小组件只读应用事先写入 App Group 的快照，不在小组件进程里跑 libgit2。数据在仓库状态变化和应用进入后台前更新。没有快照时显示空状态，而不是过期的成功状态。

### 5.9 可靠性与安全

- 同一仓库同时只跑一个写操作。第二个操作等待或明确拒绝。
- 凭据、令牌、私钥口令只进钥匙串。
- 日志和错误提示不打印令牌、口令和私钥正文。
- 崩溃不能损坏已完成的提交。克隆和导入用临时目录交换保证这一点。
- 大仓库允许失败并给出可理解的原因（内存不足、磁盘不足、网络中断、认证失败），而不是无提示退出。

### 5.10 无障碍

标准控件自带辅助功能。自定义提交图和差异行提供可聚焦的文本替代：提交说明、哈希、文件名和增删行。不只用颜色区分已暂存和未暂存。

## 6. 实现约束

工程是独立的 Xcode 工程，放在本仓库。建议分成这些目标：

- App：SwiftUI 界面与应用状态。
- Git 核心：对 libgit2 的 Swift 封装，不把 libgit2 的指针泄漏进界面层。
- File Provider 扩展：只做文件枚举和读写，通过 App Group 共享仓库根目录与「正在执行写操作」的锁。
- 小组件扩展：只读快照。

libgit2 与 libssh2 以源码静态链接，版本钉死在工程里。不依赖已经停止维护的 SwiftGit2 封装作为唯一入口；若使用封装，必须能替换其底层 libgit2 版本。

界面状态用 Swift 并发。Git 调用放在与界面隔离的执行上下文里，结果回到主执行者再刷新界面。

Android 功能对照以该仓库的 README 和 `docs/agents/architecture.md` 为准。提交图不能调用 JGit 的 `AbstractPlotRenderer`，需要自己根据提交父子关系计算车道。

## 7. 计划

每一期都遵守第 5.1 节的系统版本和玻璃规则。前一期的完成标准没有达到，不开始把下一期的功能堆进主流程。

### 第一期：外部文件夹能用的闭环

范围：

- Xcode 工程、GPLv3 许可证与第三方库声明、iOS 18 部署目标。
- 仓库根目录、列表、删除、本地初始化。
- HTTPS 克隆、GitHub Device Flow、用户名和令牌。
- 只读文件查看、提交历史、工作区差异。
- 状态、暂存、全部暂存或取消暂存、提交、pull、push。
- File Provider：列出工作区、隐藏 `.git`、允许外部保存文件、写操作进行时拒绝外部改动。
- 简体中文、英文和日语。
- iPhone 标签导航与 iPad 分栏，使用标准系统控件。

完成标准：

- 在 iOS 18 和 iOS 26 各走通第 3 节的主路径。iOS 27 若手头有系统，做同一次走查；没有则用 iOS 26 的标准组件路径作为兼容依据。
- 降低透明度打开时，导航和主要按钮仍可辨认。
- 克隆失败不会在列表里留下打不开的仓库。
- 其他应用在所选文件夹里保存的新文件会出现在状态页，提交并推送后，远程能看到该文件。

### 第二期：SSH 与分支

范围：

- SSH 克隆与推送、私钥生成、导入、口令、删除。
- 自定义 Forgejo / Gitea 账号。
- 创建和检出分支、检出标签、合并、单文件检出。
- 远程的添加和删除。

完成标准：带口令的 ed25519 密钥可以完成克隆和推送。合并冲突时列出文件并停止，不写出破损索引。

### 第三期：其余 Git 能力

范围：

- rebase、cherry-pick、reset、子模块 init 与 update。
- stash 仅通过控制台的受支持命令提供；若 libgit2 覆盖成本明显超出命令本身，stash 可以留在这一期的后半，但不许做成任意 shell。
- blame、提交图、文件夹与 ZIP 导入。
- 控制台的固定命令集。
- 仓库搜索、历史搜索、文件树搜索、置顶、标签。
- 可选的编辑器忽略模板。

完成标准：导入会拒绝第 5.2 节列出的非法输入。提交图在含合并的历史上能看出父子车道，点选某一提交能打开它的差异。rebase 冲突可以在外部改完文件后继续。

### 第四期：系统集成与收尾

范围：

- 主屏幕小组件。
- iPad 分屏和较窄宽度下的布局打磨。
- 更多语言，以及是否引入 Android 同款 OFL 字体的决定。决定引入时，字体必须支持动态字号。
- App Store 所需的隐私说明、出口合规和源码提供方式。

完成标准：小组件在仓库变脏后更新，进程被系统回收后不会显示空白却声称干净。从 TestFlight 安装的包能完成第一期主路径。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| File Provider 与 libgit2 同时碰工作区 | 写操作互斥；外部只见工作区，不见 `.git` |
| 把 `.git` 放进 iCloud 后引用被改名或变成占位文件 | `.git` 留在应用容器。用户选择的文件夹只放工作区文件，且不写入 `.git` |
| 大仓库克隆时被系统挂起或杀掉 | 只承诺前台完成；失败清理半成品 |
| 大小写不敏感导致状态异常 | 克隆和导入时设置 `core.ignorecase=true` |
| 安全作用域书签过期 | 不依赖书签存放仓库；仓库在自己的容器内 |
| iOS 27 调整玻璃外观 | 导航和工具栏只用标准组件，避免自绘玻璃皮肤 |
| libgit2 与 JGit 在 rebase、子模块上的行为差异 | 第三期按 Android 的用户可见结果验收，不按 API 形状验收 |
| GPLv3 与静态链接 | 应用以 GPLv3 发布，库的许可证和链接例外写进关于页 |
