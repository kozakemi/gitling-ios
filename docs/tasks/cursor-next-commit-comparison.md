## 交付范围

1. 在仓库提供比较入口，明确“基准提交 → 目标提交”。两端可从完整提交历史搜索、分支或标签选择，也可输入 OID；不得只查已加载页面。解析后固定完整提交 OID，引用移动不悄悄改变已选对象。交换两端后方向、增删统计和差异同步改变。
2. 直接比较两棵提交树，不默认变为 merge-base 比较。支持相同提交、非祖先提交、合并提交、detached HEAD、附注标签；拒绝不能解析为提交的输入，明确显示对象缺失和读取错误。
3. 展示变更文件列表和逐文件 diff，覆盖新增、修改、删除、模式变化和重命名。历史符号链接只展示记录的链接目标，不访问实际目标；子模块以 gitlink/OID 变更显示，不递归更新。不检出、暂存、改变索引、引用、工作区或远端。
4. 处理二进制、非 UTF-8、大文件及过大差异：先检查对象头，制定每文件及全局预算，并明确显示超限或截断，不能将跳过伪装成无差异。列表和差异按需后台加载；输入变化、交换方向和离开页面后取消旧请求，过期结果不得覆盖新选择。同步 libgit2 调用的取消边界如实说明。
5. 中英日本地化，Duo折叠/展开、窄宽度及无障碍大字号适配。文件路径、两个提交标识和比较方向应清晰；空白、错误、加载和超限状态保持顶部控件布局。
